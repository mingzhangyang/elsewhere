# Elsewhere 出生星空与纪念星图实施计划

- 版本：1.0
- 日期：2026年11月22日
- 状态：待实施，供产品修订、开发拆分与验收使用
- 适用仓库：mingzhangyang/elsewhere
- 代码基线：main 的 `24063d05f5a1829a8389245609f14351c39e1d50`，已包含 PR #20 的插画明信片地景更新。

Elsewhere 将以“出生星空”为首个明确场景，让用户输入一个有意义的日期、当地时间和地点，获得一张可以保存、赠送和分享的纪念星图，并能进入同一时空点的互动天空。首版重点是正确表达时间地点、生成完整好看的作品，以及在手机上可靠保存。

本计划沿用现有天文计算、地点搜索、时间解析和图片导出的基础。新增圆形星图作为明确标注的天体位置示意；现有探索器继续遵循真实日夜和可见性规则。先交付免费数字成品并验证实际使用，再决定作品链接、打印文件和更多样式的投入。本文中的阈值与性能数字是计划目标，实际结果在实施验收时记录。

### 面向项目的目标

新功能复用 `src/domain` 的科学计算，不建立第二套星历。创建流程和绘图代码按需加载，遵守仓库当时有效的启动体积与性能门禁。每个实现批次能够单独验收；已有探索、天气、明信片和旧分享链接维持其原有语义。

第一轮成功包含两个不同结论：功能是否可用，以及用户是否愿意留下作品。技术正确性不能被“看起来喜欢”替代；被要求执行的保存动作，也不能当作真实保存意愿。具体用户测试规则见第12节。

- 入口以“出生星空”为主，提供自定义纪念标题，不把底层模型限制为生日。

- 编辑可选标题与一句短语，预览中直接看到成品。

- 保存标准PNG；浏览器支持时，由用户主动调用系统图片分享。

- 完成中英文、键盘操作、错误恢复和手机验收。

P0对应SM0至SM4。默认关闭星座连线，首版不把连线或完整星座名称作为交付依赖。图片系统分享可先只发送图片；完整可编辑作品链接在SM5增加。

### P1 经用户验证后增加

独立作品链接与版本兼容、与原有明信片的统一创建入口、更多经过验证的输出尺寸，以及必要的分享落地体验。是否增加匿名流程统计，单独确定目的、字段和保留期，不将分析SDK作为首版依赖。

### 本轮非目标

本轮不包含占星解释、性格或命运分析、完整88星座系统、研究级星历资格认证、真实地形与历史街景还原、历史天气实拍重建、自由排版编辑器、账户体系、公共作品社区、付费、广告、实体商品生产或发货。

当前路线图明确没有商业计划，并决定在使用Open-Meteo免费服务期间不做广告、订阅或付费功能。商业化若成为后续目标，另行评估服务与数据使用条件。[现有产品决策](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/ROADMAP.md)

## 4 用户流程与界面规则

### 从入口到成品

1. 用户通过“制作我的星空”进入创建界面，默认场景为出生纪念。入口使用现有导航或分享区域附近的明确按钮，不要求用户先学会调整天空视角。

2. 选择城市后输入日期和当地时间。名字和短语都可留空；没有必填的个人身份字段。

3. 提交后先解析时间，再加载计算所需资源并生成预览。默认构图覆盖上空整个半球，用户不需要选择朝向。

4. 成品页提供编辑文字、配色、保存图片和进入天空。高级天文选项不进入首次填写表单。

5. 保存完成后，仍保留当前作品与输入；失败时保留草稿，允许重试或降低输出尺寸。

### 创建状态

创建流程应至少区分填写、输入待修正、资源加载、生成中、可预览、导出中和失败可重试。修改输入后，旧图片可以短暂保留作为上一次结果，但必须显示正在更新；新结果完成前不能将旧结果作为新输入对应的作品导出。

连续修改日期、地点或文字时，只允许最新请求更新预览。保存按钮针对一个完整且已就绪的作品快照；导出进行中不会混入随后输入的部分字段。

### 进入互动天空

创建流程提交解析后的地点与UTC时刻给现有探索状态，暂停实时播放，并使用合适的默认相机。星图的“忽略日光与天气遮蔽”规则不传入真实天空。若该时刻是白天，互动天空正常显示白天；若用户选择历史天气，继续遵循现有来源标注。

返回创建页面时保留先前的输入、文字和配色。P0只保证当前标签页会话中的草稿保留；跨刷新、跨设备收藏属于后续明确设计的功能。

## 5 日期时间与地点契约

### 输入规则

| 字段或情况   | 首版规则                                       | 用户可见的处理                     |
| ------------ | ---------------------------------------------- | ---------------------------------- |
| 日期         | 使用公历年月日，必须包含年份                   | 出生年份不能被今年替代             |
| 具体时刻     | 输入小时和分钟，秒默认为零                     | 标明是事件地点的当地时间           |
| 时间不确定   | 单独的参考时刻模式，默认当日22:00，可调整      | 输入页、预览和成品均标明参考时刻   |
| 大致知道时段 | 使用参考时刻模式并调整参考值                   | 仍标记为参考，不升级为精确出生时刻 |
| 城市         | 必须选中搜索候选项或现有预设                   | 显示城市、州省和国家，区分重名地点 |
| 时区         | 采用所选地点的IANA时区                         | 不使用设备当前时区替代             |
| 海拔         | 使用现有可信来源；缺失时采用项目已有假设并记录 | 不要求普通用户填写                 |

“当日22:00”是计算参考值，不代表那时一定天黑。在高纬夏季等情况下仍使用相同规则，作品称为日期纪念星图。参考时刻也必须通过当地时间有效性检查。

### 两种时间状态

具体时刻保存用户输入的当地日期、当地钟表时间、IANA时区，以及解析后的UTC时刻、UTC偏移和必要的重复时间选择。这里的“具体”表示用户提供了一个时刻，不表示系统认证了出生记录。

参考时刻保存用户选择的当地日期，并使用独立的参考对象记录参考钟表时间、选择来源、解析后的UTC和偏移。禁止将“不知道时间”悄悄填为00:00后当成具体时刻保存。偏移使用完整字符串或秒数，不假定历史偏移都是整分钟。

### 修改地点的语义

在纪念表单内修改地点，保留用户已经填写的当地日期和钟表时间，按新地点重新解析UTC，清除原来的重复时间选择。现有探索器继续采用“保持UTC时刻，改变所在地显示时间”的行为。两套界面状态分开，只有提交或进入探索时进行转换。

### 边界与异常

- 春季切换等原因造成不存在的当地时间时，说明该钟点不存在，要求修正；不能自动前移或后移。

- 一个当地时间出现两次时，列出两个UTC偏移并要求选择，随后将选择写入作品。

- 输入范围以解析后的UTC为准：1900-01-01 00:00:00至2100-12-31 23:59:59.999。界面提示与现有项目范围保持一致，边界通过UTC校验。

- 地点切换、午夜前后、跨日和闰日均以目标地点的民用日期为准。

- 分享作品将来重新打开时，以保存的UTC时刻恢复原来的瞬间，并保留原始民用时间与偏移；运行时时区规则变化不能静默改写作品。

保存与读回都检查时间字段的内部一致性：UTC加已保存的offset，必须还原记录的当地日期和钟表时间；参考模式对独立参考对象执行相同检查。内部字段矛盾的作品应拒绝。若记录本身自洽，只是与当前运行时的IANA解析结果不同，则按保存的UTC恢复，并保留原时区记录；这类规则更新不能被当作普通损坏数据处理。

复用 `wallTimeCandidates`、`zonedDateTimeToUtc`、`validateInstant` 和 `ensureTemporal`。当前实现使用浏览器Temporal或按需加载的polyfill，不能在作品中填写一个未经实际固定的tzdb版本。来源：[时间解析](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/time.ts)、[Temporal加载](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/temporal.ts)。

## 6 星图的科学与显示规则

### 天空范围与投影

本计划中的全天穹指观察地点地平线上方的整个半球。采用方位等距投影：天顶在圆心，地平线在圆周，北在上、东在左，四个方位清楚标注。它表达仰望天空的方向，不能照搬地理地图的东西方向。

设天体标准折射后的中心高度为 `alt`，方位角为从北顺时针计量的 `az`。采用如下归一化规则，三角函数输入须转换为弧度：

```text
r = (90 - alt) / 90
x = cx - R * r * sin(az)
y = cy - R * r * cos(az)
```

仅绘制中心视高度不低于0度的天体，并对图形做圆形裁切。天顶映射圆心；北、东、南、西的地平线分别映射圆周上、左、下、右。投影不依赖现有相机朝向、屏幕宽高比或用户之前的视场角。

### 坐标口径

v1沿用项目已经提供的标准大气折射视高度，太阳、月亮、行星和恒星统一使用这一口径，不混入部分天体的几何高度。圆图按天体中心定位，不直接复用现有太阳和月亮的 `visible` 标志；该标志可能允许中心仍略低于地平线而圆面上缘已升起的情况。来源：[天文计算](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/astronomy.ts)、[恒星坐标](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/stars.ts)。

### 示意模式的可见规则

| 要素           | 圆形纪念星图的规则                                       |
| -------------- | -------------------------------------------------------- |
| 时间           | 始终使用用户选择或明确采用的参考时刻                     |
| 恒星           | 从既有星表选取，默认星等上限为6.0，并保存显示规则版本    |
| 日光与天气     | 不据此隐藏恒星；不绘制历史云层遮挡星图                   |
| 光污染与月光   | 不影响默认星图是否画出某颗恒星                           |
| 太阳月亮行星   | 中心在地平线上方时按计算位置绘制符号                     |
| 地平线下天体   | 不移入圆内；必要时以图外说明表示它位于地平线下           |
| 星点与天体符号 | 大小用于清晰表达，属于示意比例；位置不能为美观移动       |
| 标签           | 可避让、减少或使用引线；不得挪动天体锚点                 |
| 月相           | 使用同一计算快照的相位和朝向；不使用与日期无关的装饰月亮 |

作品保留一句简短说明：天体位置示意，未模拟日光与天气遮蔽。白天场景额外说明当时为白天；参考时刻场景保留其采用时刻。图中星点密度由可记录的星等和样式策略控制，不添加没有坐标依据的装饰星。

月相比例复用同一计算快照，但月牙在圆图中的屏幕朝向需要重新求取：将亮缘在天球上的切向方向通过新投影的局部方向变换映射到画布。方位等距投影不是保角投影，不能把原有局部天空画面的旋转角直接用于圆图。实现应处理天顶附近方向不稳定的情况，并验证月亮位于圆图四个象限、近天顶和近地平线时的朝向。

现有晴空预览仅清除云雾与降水，仍会受到日光、月光和光污染模型影响，因此不能用它代替纪念星图模式。[既有恒星可见性模型](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/starVisibility.ts)

### 星座连线与精度声明

P0默认不显示连线。当前只有北斗、猎户、南十字和夏季大三角四组简化连线；如果后续提供开关，应称为简化示意连线，不能标为完整88星座。线段需要沿球面采样并在地平线处裁切，不能直接连接两个可能跨越圆边界的投影端点。[现有连线数据](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/stars.ts)

产品定位继续是教育和纪念用途。支持日期范围与独立验证范围分别记录，不宣称所有历史日期已获得研究级精度认证。新功能首先保留现有科学回归预算，再扩充代表历史年代的独立参考样例。[科学约定](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/docs/SCIENCE.md)

## 7 作品内容与视觉规格

### 默认版式

圆形星图占据画面主要部分，下方排列纪念标题、地点和日期时间，再放一行可选短语。科学说明和数据署名放在可读的底部区域。默认提供深蓝与浅纸两种配色，共用同一布局，不增加自由拖拽排版。

标题最多40个可见字符，短语最多80个可见字符；字符计数考虑中文、组合字符和emoji。允许合理换行，不能以无限缩小字号容纳长文。中英文分别检查行高与断行。用户文字始终作为纯文本处理。

具体时刻作品可以使用“你来到世界的那一刻”等标题；参考时刻作品默认使用“属于这一天的星空”等不暗示精确出生瞬间的标题。用户可自定义文字，但系统生成的时间说明不能被自定义标题替代。

### 必需信息与可选信息

默认显示城市名称、当地日期、计算采用的时刻和时区偏移。标题与短语可选，不要求真实姓名。精确经纬度默认不印在图片上。允许将具体出生钟点从主要装饰文字中隐藏，但若作品采用参考时刻，底部仍须保留明确的参考说明。

图像始终保留必要来源署名和示意模式说明。若无历史天气数据，圆形星图正常生成；画面不使用“真实天气已还原”等表述。

### 标准输出

P0目标版式为4比5，标准PNG建议为1200乘1500像素。预览和导出共享归一化布局与同一作品快照；该规格面向数字保存和分享，不承诺大幅打印质量。仅在真机验证通过后提升默认尺寸。

高分辨率输出作为SM6独立工作，依据目标打印尺寸与像素密度生成，不能简单放大已有1200像素位图。现有明信片继续保留自身版式与尺寸规则，首版不强行改为星图版式。

### 模块职责

以下路径为建议名称，实施前依仓库约定调整，保持职责边界。

| 模块               | 建议位置                               | 职责                                         |
| ------------------ | -------------------------------------- | -------------------------------------------- |
| 事件输入与时间解析 | `src/lib/memorialTime.ts`              | 表单状态、具体与参考时刻、地点变化语义       |
| 作品定义与校验     | `src/lib/skyArtwork.ts`                | 作品模型、字段限制、显示意图、版本迁移       |
| 圆形投影           | `src/domain/skyChartProjection.ts`     | 无浏览器依赖的高度方位到圆图坐标映射         |
| 星图快照与选取     | `src/domain/skyChart.ts`               | 使用现有天文结果，生成星图所需天体与元数据   |
| 绘图与排版         | `src/moment/skyChart.ts`               | 共享布局、Canvas绘制、文字避让、署名         |
| 创建界面           | `src/components/SkyArtworkCreator.tsx` | 表单、预览、编辑和错误恢复                   |
| 轻量创建宿主       | 应用入口与独立创建Shell                | 直接创建时不挂载完整探索器，进入天空时再交接 |

`src/domain`继续保持与UI、网络、渲染器无关。新圆图无需启动WebGL场景或请求天气，即可使用现有计算能力完成生成。现有 `MomentSnapshot` 为明信片要求天气字段；新星图使用独立快照，不伪造天气满足旧类型。[现有快照定义](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/lib/moment.ts)

P0采用轻量创建宿主，通用直接入口建议为 `#create`，不含个人数据。应用入口先选择宿主：直接创建时只挂载表单与星图所需模块；点击“进入天空”后才挂载完整探索器。不能仅在已经运行的探索器上增加弹层，却声称直接创建不启动WebGL和天气。从已打开的探索器转入创建时，按既有生命周期清理后台工作，并在上层会话状态保留返回所需数据。具体入口命名在SM0固定，旧 `#sky=` 路径保持原有行为。

### 作品契约

| 字段组     | 必须表达的内容                                        | 约束                               |
| ---------- | ----------------------------------------------------- | ---------------------------------- |
| 标识与版本 | 作品类型、schema版本、创建格式版本                    | 与旧Exploration契约分开            |
| 地点       | 显示名称、地区国家、计算经纬度、采用海拔、IANA时区    | 以城市级地点为默认输入             |
| 时间       | 具体时刻或参考时刻联合类型，原始民用时间、UTC、offset | 不丢失用户意图及消歧选择           |
| 内容       | 纪念类别、标题、短语、显隐设置                        | 纯文本，长度有上限                 |
| 设计       | 版式、配色、图层、星等阈值、作品语言                  | 不依赖接收人的本地偏好             |
| 计算来源   | 实际引擎版本、星表标识与哈希、坐标和投影规则版本      | 来源从构建和资源元数据取得         |
| 绘制来源   | 排版规则、绘制版本、已使用资源标识                    | 不把版本号等同于永远保存旧运行环境 |

作品界面语言可以跟随接收人设置；作者写下的文字和作品语言保持保存值。P0建立模型并用于本地流程，SM5才实现公开可传递的序列化入口。

### 就绪与错误边界

Temporal、星表和所需字体就绪之后才能生成可导出的快照。当前星表异步加载，初始为空；资源未加载成功时不能将“没有星点”误判为有效天空。字体失败应采用明确的可用回退并重新排版，或提示重试；不能在导出后再改变文本布局。[星表加载状态](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/domain/stars.ts)

资源状态、输入解析错误和绘制失败分开处理。地理编码失败只影响新地点查找；已选定地点的星图不依赖历史天气或在线天气服务。各异步步骤需要取消或请求序号机制，过期结果不能覆盖新作品。

## 9 保存分享与信息处理

### PNG与手机保存

标准导出一次只生成一个大画布，并限制长边和总像素数。处理Canvas绘制异常、`toBlob`返回空、字体未就绪和旧请求覆盖等情况；清理Object URL和临时画布。失败时只允许有限的降级重试，例如从1200乘1500降至960乘1200，并明确显示实际尺寸。

系统文件分享可用时提供分享；不可用时仍提供PNG下载。系统分享被用户取消不作为错误，也不统计为成功发送。下载被调用不等于文件已进入相册，真机测试需检查最终文件可打开、内容正确。现有导出组件已有请求序号和资源释放模式，可复用。[当前导出组件](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/components/MomentImage.tsx)

### 完整作品链接

SM5使用独立的 `#artwork=` 或同等明确的新入口，旧 `#sky=`继续交给原解析器。新链接记录所共享的作品模型；输入长度、文本长度、版本、坐标与时间均有严格校验。不支持的版本说明原因，不能静默打开现在的天空。

链接解析执行第5节的UTC、offset与当地日期时间一致性检查；“每个字段分别合法”不足以接受整个作品。时间记录自洽但运行时时区规则改变的情况，与字段自相矛盾的损坏链接分别验收。

链接应恢复相同的地点、UTC时刻、时间已知程度、作品语言与受支持的设计规则。算法、字体和浏览器变化可能改变细节；长期保留当时确切画面依靠PNG，链接不承诺多年后像素完全相同。

用户在生成链接前能查看共享内容，并选择是否包含纪念文字；不包含文字时接收方得到通用标题。即使隐藏图片上的时间文字，可重现星图的链接仍需要携带可确定该时刻的数据，不能将文字隐藏描述为从链接删除了出生时间。只想发图的人可以仅分享PNG。

P0和SM5不依赖服务端短链或聊天软件的个性化预览卡。URL片段不会随普通HTTP请求发送给站点服务器，但持有链接的人和页面脚本可以读取它，因此链接不能称为加密或秘密保存。当前网站分享也是片段状态模式。[现有分享契约](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/src/lib/persistence.ts)

### 信息处理原则

出生日期、时刻、姓名与短句不提交给分析服务，不拼接到地理编码请求或错误日志中。地点搜索会把检索词发送给既有地理编码提供方，说明应如实区分这一点。默认不启用设备定位，不建立服务端出生资料档案，也不自动公开作品。

测试记录使用虚构样例或参加者自愿选择的数据，只记录场景类别、操作表现和匿名反馈。截图及测试夹具不保存真实完整出生资料。图片按实际使用的数据保留必要署名；新画风、字体或资源应沿用项目的来源登记流程。

### SM0 范围与基线

本文件通过文档PR接入仓库，并由ROADMAP链接，用于细化原阶段3和阶段4。该PR仅提交计划与路线图衔接，不包含应用功能实现。实施时再次核对最新main、开放PR、仓库说明和已有改动，登记实际实施对应的代码版本。

冻结具体与参考时间、白天模式、地平线口径、默认配色、文字限制和标准尺寸。准备虚构样例：北半球、南半球、白天、时间不确定、异地时区、DST和日期范围边界。定义独立参考来源、量的单位和容差，不以截图相似替代数值依据。

### SM1 事件输入与时间

先实现可独立验证的输入模型和时间解析，再接表单。允许在开发夹具中查看解析结果，避免把工程调试信息塞入正式用户流程。输出稳定的作品基础模型，并证明切换地点不会误用探索器保持UTC的语义。

完成条件包括零个、一个、两个当地时间候选的处理，参考时刻说明，失效输入阻止生成，以及模型和探索交接中目标地点日期的一致性。预览与文件名在SM3验收，新作品链接在SM5验收。

### SM2 圆形星图核心

实现纯投影函数和天体选取策略，复用同一 `calculateSky` 计算入口。独立于天气和WebGL完成基础绘制。首先检查天顶和四方位，再验证南北半球、地平线附近、白天、月亮在地平线下，以及历史日期。

完成条件是所有天体锚点来自计算结果，星图显示策略不污染真实探索，科学口径和参考数据在文档中有记录。

### SM3 完整作品流程

连接轻量创建宿主、入口、表单、星图预览、标题短语、两种配色、PNG下载和系统分享。直接打开创建入口时不挂载完整探索器；复用统一布局函数生成预览与成品，完成“进入这一刻的天空”和返回草稿。对加载、失败、取消和连续修改设置提供明确状态。

完成条件是一个新用户从入口可以获得完整作品；不需要先调整相机，不会导出上一次输入的图片；英文与中文都能正确显示。

### SM4 质量与用户试用

执行第11节中标为P0的测试及现有本地门禁，完成至少一台真实iPhone Safari和一台有代表性的Android浏览器测试。随后按第12节进行5至6人任务观察，先修正确性和理解问题，再处理视觉或入口问题。

实现者负责提供可测试版本、脚本和匿名记录模板；项目负责人安排试用者与设备持有人完成真机操作。截图、录屏或任务记录注明版本与设备，不包含真实完整出生资料。外部测试证据尚未取得时，状态保持“开发完成，SM4待验收”，不能以模拟器结果代替真机完成。

如果使用者能完成但不愿保存，先根据具体原因调整默认成品或定位；如果普遍不理解时间假设，先调整输入和说明；若修正后兴趣仍弱，保留已有能力并暂停SM5和SM6。该结果不意味着把试用数据包装成市场规模结论。

SM4达到质量门槛并完成产品判断后，可以直接开放免费PNG版本，发布仍须满足第13节的发布检查。完整作品链接不作为该版本上线的先决条件。

### SM5 作品链接扩展

在P0有清楚使用信号后，实现独立作品序列化、新链接解析、损坏和不支持版本的处理、共享字段预览及旧链接回归。接收者应先理解作品，再决定进入天空或创建自己的作品。

新链接版本发布同样核对原有发布门禁，记录版本、已通过检查、剩余限制和回退路径。该阶段针对接收者理解、重开和再次创建的实际需要，不因既定编号而自动实施。

### SM6 按证据扩展

只有用户明确提出打印需求，才增加按实际尺寸绘制的高分辨率PNG或PDF；只有连线或更多样式影响使用，才增加对应内容。聊天预览卡、短链、账户收藏和商业化各自属于独立提案，不自动进入必做清单。

| 月牙朝向   | 月亮处于四象限、近天顶和近地平线         | 亮缘方向经新投影转换，不能只校验照明比例  | P0      |
| 历史计算   | 1900、1950、1980、2000及2100附近代表样例 | 按记录的独立参考与科学预算比较            | P0      |
| 资源       | 星表慢加载、失败、字体回退               | 不导出未就绪结果，可重试                  | P0      |
| 直接入口   | 新标签页直接打开创建界面                 | 未进入天空前不创建WebGL场景或启动天气请求 | P0      |
| 异步更新   | 连续改变日期、城市、文字                 | 只有最新完整快照成为可导出结果            | P0      |
| 文案       | 长中文、英文、组合字符及emoji            | 不裁切、不注入HTML、长度限制合理          | P0      |
| 手机输出   | 下载、分享取消、不支持文件分享           | 成品可用，取消不误报，下载有回退          | P0      |
| 旧链接     | 已有 `#sky=` 和旧偏好                    | 保持既有解析与探索语义                    | P0与SM5 |
| 新链接     | 具体或参考时刻、损坏内容、未知版本       | 属性正确恢复；错误不打开错误天空          | SM5     |
| 时间一致性 | 字段各自合法但组合矛盾；运行时规则已变化 | 拒绝内部矛盾，保留自洽的已保存时刻        | SM5     |
| 接收偏好   | 不同配色、亮度与语言偏好                 | 作品采用保存的设计意图                    | SM5     |

数值、交互和视觉证据分开。新投影使用有独立预期的测试；天文位置沿用现有SCIENCE预算，例如太阳月亮与行星几何高度和方位的0.02度回归上限，同时保持各参考的坐标约定一致。近天顶方位等病态量应改用合理的方向差比较并单独记录，不能放宽全部样例掩盖错误。标准折射的呈现与无折射独立参考分层验证；现有恒星0.05度检查是同引擎一致性检查，不能替代独立历史参考。[现有预算与限制](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/docs/SCIENCE.md)

历史星位独立核对需要固定相同星表、历元、参考系、岁差与自行约定，并记录所用工具或数据版本。先验证方向和代表亮星，不能用两个共用错误函数的输出相互证明正确。若某个年代或场景超出预算，记录误差来源、调整模型或缩小承诺范围后再发布。

## 12 用户验证与产品指标

### 参加者与任务

首轮5至6位不熟悉应用的人，至少覆盖知道具体出生时刻、只知道日期、白天出生和异地时区四种情况，条件可以重叠。至少两位使用自己的手机；不要求提交真实出生资料，可以采用另一个自愿选择的纪念时刻。

先给任务“做一张对你有意义的日期和地点的星图”，观察完成过程，记录所需提示、阻塞和时间。结果出现后请参加者说明图的含义、采用的时刻，以及白天或参考时间如何处理。为了验证可用性而要求其找到保存按钮的动作，单独记录。

最后让参加者自由决定是否保留作品、发给某个人或再做一张，不催促分享。记录实际动作及理由，并问最想改变的一个地方。沿用仓库现有的观察原则与记录结构。[测试脚本](https://github.com/mingzhangyang/elsewhere/blob/24063d05f5a1829a8389245609f14351c39e1d50/docs/SKY-MOMENT-TEST.md)

### 阶段判断标准

| 维度         | 标准或观察信号                                                      | 未达到时的动作                   |
| ------------ | ------------------------------------------------------------------- | -------------------------------- |
| 可用性门槛   | 6人中至少5人，或5人中至少4人，无指导完成生成并找到保存；目标约2分钟 | 优先修入口、表单和错误恢复       |
| 理解门槛     | 每位参加者经查看页面能正确解释具体或参考时刻及位置示意含义          | 调整命名与说明，再进行针对性复测 |
| 正确性门槛   | 错时区、错日期、地平线规则错误和空白成品等关键缺陷为零              | 阻止发布，先修缺陷               |
| 保存意愿信号 | 至少3人在任务结束后主动保留结果                                     | 查明视觉、个性化或用途上的问题   |
| 分享意愿信号 | 至少2人自愿发送给具体的人                                           | 记录阻碍；不把口头意愿替代发送   |
| 再次使用信号 | 单独记录主动制作第二张的行为                                        | 判断其他纪念场景是否更有吸引力   |

前3项是质量门槛，后3项是产品投入信号，不能互相替代。约2分钟从创建界面可操作开始计时，地点搜索和冷资源等待单独记录；同时保留真实总耗时，避免掩盖等待造成的体验问题。

这些人数是投入决策的操作性参考，不是统计显著的市场验证。若保存意愿清楚但分享较弱，可以先开放已验收的个人保存用途；是否进入SM5取决于链接和接收体验的实际需要。保持成品可用与继续扩展功能是两个决策。

### 后续观察指标

公开体验后，优先观察创建进入、有效提交、预览完成、导出成功、主动分享调用及接收者再次创建。每项都使用明确分母：例如导出成功率以导出尝试为分母，创建完成率以开始创建为分母。分享API完成只能表示分享流程完成，不能证明接收人收到或打开。

P0采用人工观察和本地测试记录。若后续增加匿名统计，只记录事件类别、版本、耗时区间和非敏感错误码，不记录出生年月日、UTC时刻、坐标、名字、短句或完整链接。接收者转化若没有合适的匿名测量方案，则先通过试用访谈观察，不建立不必要的跨用户追踪。

## 13 性能实施与发布约束

### 性能目标

首版以代表性手机为测量基线。资源已加载且地点已确定时，目标为提交到预览不超过1秒、标准PNG导出不超过5秒；冷启动、星表下载和地点搜索分别记录。若目标设备达不到，应先降低绘图开销或输出尺寸，并更新实测记录，不将未测数字写成已达成指标。

创建代码和绘图模块按需加载；不因新入口把绘图、字体或新依赖加入主启动包。沿用仓库有效的体积预算，不为让构建通过而单纯提高预算。星图不启动天气请求，也不依赖天气服务成功才能生成。

### 实施与PR组织

每批实施前核对最新main、开放PR和仓库说明，复用已经合并的能力。按依赖顺序提交范围清晰的PR；前一批合并后再基于最新main继续，避免堆叠PR和重复开发。产品文案、科学规则和类型契约随对应实现一起更新。

默认进行本地验证，不主动触发或重跑CI。推送前按实际workflow确认不会触发不符合当前要求的CI；不能把跳过标记当作所有触发器都生效的保证。验证先围绕变更风险，再执行仓库必要门禁，避免与实际风险无关的重复测试。

使用当时仓库定义的 `npm run validate`、格式检查及需要的浏览器检查，记录提交号、命令、结果和真机条件。任何尚未执行的真机或独立参考检查保留待办状态。

### 发布与回退

SM4通过后，免费PNG版可以独立进入发布检查；SM5不是其前置依赖。每次公开版本都应满足对应范围的原有发布门禁，并按实施会话明确的发布授权执行。

新入口具有简单的可关闭开关或等效回退路径。关闭新入口后，原有探索和 `#sky=` 链接仍可使用。P0验证静态资源与离线缓存更新；增加SM5后再验证新旧链接解析优先级与作品契约版本，避免旧缓存混用新契约。

发布检查记录默认尺寸、支持浏览器、时间范围、已知限制、版本和回退操作。收费、短链、服务端预览及数据提供方迁移不与首版发布混在同一批次。

## 14 风险与应对

| 具体风险                   | 对用户的影响                 | 应对与验收                                 |
| -------------------------- | ---------------------------- | ------------------------------------------ |
| 当地时间误用为设备时间     | 得到另一个时刻的天空         | 独立输入模型，跨时区与DST测试              |
| 未知时刻被包装为精确时刻   | 误解作品含义                 | 联合类型，输入与成品持续显示参考说明       |
| 白天星图被理解为夜空实拍   | 产品承诺失真                 | 明确位置示意，真实探索保留白天             |
| 原有晴空预览被当作星图模式 | 日光仍抑制恒星或影响探索规则 | 独立星图选取策略                           |
| 圆图方向或地平线规则错误   | 星位位置错误                 | 四方位独立预期、中心高度筛选、跨半球样例   |
| 字体或星表未加载就保存     | 空白星图或文字错版           | 资源就绪门槛与失败恢复                     |
| 手机导出内存过高           | 页面重载或文件失败           | 标准尺寸、限额、单画布与有限降级           |
| 链接未包含完整显示策略     | 接收者看到不同设计           | 独立作品契约和偏好隔离                     |
| 相近纪念时刻视觉差异有限   | 用户觉得缺少个人意义         | 标题与短语承载故事，不宣传每张都视觉上唯一 |
| 小样本好评导致范围扩张     | 过早投入复杂平台功能         | 以自愿行为和具体需求决定SM5及SM6           |

## 16 完成定义与维护方式

### P0完成定义

- [ ] 出生或自定义纪念时刻能从直接入口创建。

- [ ] 具体时刻、参考时刻、地点变化、DST与UTC边界按契约处理。

- [ ] 圆形星图采用一致坐标口径，方位和地平线正确。

- [ ] 标题、短语、配色与必要说明进入成品。

- [ ] 天气缺失不阻断，星表和字体失败可恢复。

- [ ] 中文英文、键盘操作和手机输出检查完成。

- [ ] 必要本地门禁与真机证据有明确版本记录。

- [ ] 5至6人试用完成，保存与分享意愿独立记录。

- [ ] SM5继续、调整或暂缓的理由已登记。

### 后续维护

本计划作为产品和实施说明；ROADMAP保持全局阶段与优先级，SCIENCE维护科学约定和误差预算，VALIDATION保存实测证据，RELEASE保存发布门禁。相同规则使用链接衔接，减少多份文档相互矛盾。

每个任务记录状态、关联PR、实际提交号、验收结果和剩余问题。状态使用待实施、进行中、待验收、完成、暂缓；只有满足验收且代码已进入约定分支，才标记完成。调整默认规则时记录原因及受影响的模型、图片和链接版本。

下一次实施从SM0开始：核对最新基线与本计划，完成剩余规则核对和样例设计，然后实施SM1的事件输入和时间契约。首次代码批次不同时进行天空视觉重设计、数据提供方迁移或大型分享后端开发。
